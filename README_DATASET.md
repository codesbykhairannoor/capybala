## 📌 Overview

**Llama-Agent-Deadlock** is the first systematically curated empirical dataset capturing **multi-step cognitive deadlocks, cascading error loops, and context-overflow failures** in autonomous software engineering agents powered by **Meta Llama-3-70B**.

While modern evaluation leaderboards report flat resolution rates, they disguise the primary underlying failure mode of autonomous agents: **Autoregressive Error Propagation**. When an agent encounters a bash traceback or test failure, intermediate reasoning context becomes poisoned by error logs, trapping the agent in non-progressive iteration loops until its context window or budget is depleted.

This dataset was parsed and extracted from official execution logs of `SWE-agent-llama-70b` across real-world GitHub repositories, structured into a clean tabular schema for statistical modeling, agent guardrail design, and runtime middleware evaluation.

---

## 📊 Key Empirical Findings

From our empirical analysis across the benchmark:
* **70.0% Deadlock Rate**: 70% of autonomous Llama-70B trajectories exhibit severe cognitive deadlocks ($\ge 3$ repeated terminal commands or context-overflow termination).
* **3x Token Inefficiency**: Deadlocked agents average **69.8 execution turns** compared to **22.5 turns** for non-deadlocked instances, burning over 65% of inference compute on redundant bash invocations.
* **Context Overflow Epidemic**: 32.5% of total failures are directly caused by `exit_context` (context window saturation from unpruned error tracebacks).

## 📁 Dataset Schema & Data Dictionary

| Column Name | Type | Description |
| :--- | :--- | :--- |
| `instance_id` | `string` | Unique identifier of the GitHub repository issue (e.g., `AnalogJ__lexicon-336`). |
| `model_name` | `string` | Backbone model (`swe-agent-llama-70b`). |
| `repo` | `string` | Target open-source repository name. |
| `total_turns` | `int` | Total multi-turn interactions (Agent Thought + Terminal Execution + Feedback). |
| `ai_action_count` | `int` | Number of distinct actions generated by the model. |
| `total_commands_executed` | `int` | Total bash/shell commands invoked. |
| `unique_commands_count` | `int` | Count of unique commands after deduplication. |
| `max_single_command_repetition` | `int` | Maximum frequency of any single command repeated across turns. |
| `error_feedback_count` | `int` | Number of times the environment returned a Traceback or Failure. |
| `loop_detected` | `int (0/1)` | Binary indicator (`1` if agent experienced cognitive deadlock, `0` otherwise). |
| `loop_onset_step` | `int` | The execution turn where the first command repetition was initiated (-1 if no loop). |
| `wasted_turns_ratio` | `float` | Estimated fraction of execution turns spent in unproductive loops (0.0 to 1.0). |
| `exit_status` | `string` | Official SWE-bench exit status (`submitted`, `submitted (exit_context)`, etc.). |
| `failure_diagnosis` | `string` | Diagnostic category (`Context_Overflow_Deadlock`, `Cognitive_Iteration_Deadlock`, etc.). |
| `resolved_target` | `int (0/1)` | Ground truth whether the issue was successfully solved (`1`) or failed (`0`). |

## 🔬 Mathematical Formulation of Agent Deadlock

Let $\mathcal{A} = (a_1, a_2, \dots, a_T)$ denote the sequence of actions taken by the autonomous agent, and $\mathcal{O} = (o_1, o_2, \dots, o_T)$ denote the terminal observation feedback. 

A **Cognitive Deadlock State** at step $t$ is formalized as:
$$\exists\, k \ge 2 \quad \text{s.t.} \quad \text{Sim}(a_t, a_{t-k}) \ge 1 - \epsilon \quad \land \quad \text{IsError}(o_{t-1}) = \text{True}$$

Under standard autoregressive generation without supervisory intervention, the transition probability into successive errors satisfies:
$$P(\text{Error}_{t+1} \mid \text{Error}_t, \text{Loop}_t) \gg P(\text{Error}_{t+1} \mid \text{Success}_t)$$
